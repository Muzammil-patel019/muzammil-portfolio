Capstone: own a small automation project

Build a local task app with a login form, task creation, validation and a small JSON API. Use test accounts and disposable data.

  1. Plan: write acceptance criteria, risks, five positive and five negative scenarios. Decide what belongs at unit, API and UI levels.
  2. Build: create pytest unit tests, API checks with timeouts, and one browser journey. Use page/service objects and fixtures with cleanup.
  3. Break: deliberately remove a validation check. Show which test catches it. Introduce delayed rendering and replace a fixed sleep with a meaningful wait.
  4. Automate: run smoke tests on a pull request and the full suite on a schedule. Collect reports, screenshots and traces even when tests fail.
  5. Explain: present your architecture, test data strategy, a real failure, a tradeoff and the remaining coverage gaps. Report measured results only.

Ready to demonstrate: another person can follow your README, run your tests, see a meaningful failure, and understand how you diagnosed it.
